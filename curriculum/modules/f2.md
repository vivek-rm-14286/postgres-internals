# f2 — Working with Data (build plan)

Audience: beginners moving to intermediate. Every result below was run on PGlite (PostgreSQL 18.6, UTF8, TimeZone UTC by default).
Scratch scripts: `scratchpad/f2/*.sql`, `cap.mjs` (cast matrix, division table, 0.1 sums).

## 1. text-functions — Text and strings
Facts
1. `||` concatenates; one NULL makes the whole result NULL: `'a' || NULL` → NULL (functions-string).
2. `concat` ignores NULL args (`concat('a',NULL,'b')` → `ab`); `concat_ws(', ','Ann',NULL,'Lee')` → `Ann, Lee` (functions-string).
3. `||` accepts a non-string on one side: `'Value: ' || 42` (functions-string).
4. `length`/`char_length` count characters, `octet_length` counts bytes: `josé` 4 vs 5, `😀` 1 vs 4 (functions-string).
5. `lower/upper/initcap`: `initcap('hello wORLD o''neil')` → `Hello World O'Neil` (functions-string).
6. `trim` removes spaces by default; `ltrim('00123')` stays `00123`, `ltrim('00123','0')` → `123` (functions-string).
7. `substring(s FROM start FOR n)`, positions start at 1; `substring('PostgreSQL', 0, 3)` → `Po` (virtual position 0) (functions-string).
8. `position('SQL' IN 'PostgreSQL')` → 8; 0 when absent; `strpos` has the reverse argument order (functions-string).
9. `split_part(s, delim, n)`; negative n counts from the end (PG14+); past the end → empty string (functions-string).
10. `format()`: `%s` value, `%I` identifier (quoted if needed), `%L` literal (NULL → `NULL`) (functions-string).
11. Regex: `~` matches anywhere unless anchored, `~*` case-insensitive; `regexp_replace(..., 'g')` replaces all; `regexp_match` returns first match groups; `regexp_matches(...,'g')` returns one row per match and drops rows with none (functions-matching).
12. `LIKE` must match the whole string; `ILIKE` is case-insensitive (functions-matching).
13. `citext` compares case-insensitively; `UNIQUE` on citext rejects `Ann@x.com` vs `ann@X.COM` (citext).
14. Nondeterministic ICU collation (`deterministic = false`) makes `=` case-insensitive; ILIKE and regex are not supported with it (error), LIKE is (collation, functions-matching).
Visualizer: string workbench. Editable input (presets: padded name, email, accented text with emoji). Function picker. Input and output drawn as character tiles with a UTF-8 byte count under each tile; matched/kept/removed characters highlighted; live `length` vs `octet_length` tiles. "Next function" button = viz-next.
Playground: `customers(name, email, phone, city)` with messy data; presets: concat & NULL, length vs bytes, clean-up (trim/initcap/lower), split & position, regex phone/email, case-insensitive (lower + citext).
Production: dedupe sign-ups whose emails differ only by case/spaces → normalise + unique index on `lower(email)`.
Pitfalls: `||` with NULL blanks a whole label; `varchar(n)` counts chars not bytes / octet_length surprises; regexp_matches dropping rows; case-insensitive search via `lower()` with no expression index.
Going deeper: Internals *Designing indexes* (expression indexes).

## 2. numbers-and-math — Numbers and arithmetic
Facts
1. integer/integer truncates toward zero: `7/2` → 3, `-7/2` → -3 (functions-math).
2. `%`/`mod` takes the dividend's sign: `-7 % 3` → -1 (functions-math).
3. Any numeric operand promotes: `7.0/2` → `3.5000000000000000` (numeric); `7/2::float8` → 3.5 (functions-math, typeconv).
4. Literal types: `1` integer, `3000000000` bigint, `1.5` and `1e3` numeric (typeconv, verified pg_typeof).
5. Overflow is an error, never wraparound: `2147483647 + 1` → `integer out of range` (datatype-numeric).
6. float8 is binary: `0.1+0.2` → `0.30000000000000004`; numeric → `0.3`; 10×0.1 summed → `0.9999999999999999` vs `1.0` (datatype-numeric).
7. `numeric(p,s)`: rounds to s decimals, then errors if integer digits > p−s: `12.345::numeric(5,2)` → 12.35, `1234.5::numeric(5,2)` → `numeric field overflow` (datatype-numeric).
8. `round(2.5)` numeric → 3 (ties away from zero); `round(2.5::float8)` → 2 (ties to even) (datatype-numeric).
9. `round(x, -2)` rounds to hundreds; `trunc` cuts; `ceil(-2.3)` → -2, `floor(-2.3)` → -3 (functions-math).
10. `^` is left-associative: `2^3^2` → 64 (functions-math).
11. Division by zero errors for int, numeric and float8 (verified).
12. `random()` is in [0,1); `random(1,6)` is inclusive (PG17+); `setseed` makes it repeatable; not cryptographic (functions-math).
13. `avg(int)` returns numeric; `sum(x)/count(x)` on ints truncates (functions-aggregate, verified 1 vs 1.6666666666666667).
14. `money` is locale-dependent; prefer numeric for money (datatype-money).
Visualizer: three tabs. Division lanes (pick a, b: int vs numeric vs float8 result + result type, captured). 0.1 drift slider (float8 vs numeric sum, captured for n=1..10). numeric(p,s) box (steppers for p, s; value picker; exact decimal rounding computed in JS with half-away-from-zero; overflow card). viz-next advances the active control.
Playground: `line_items(price numeric(10,2), qty int, weight_kg real)`; presets: integer division trap, types of literals, float vs numeric, rounding family, numeric(p,s) overflow, percentages without truncation, random.
Production: invoice totals drifting by a cent → numeric(12,2) and round once per line.
Pitfalls: `count_a / count_b` = 0; float money; ratio * 100 order; overflow of int sums/ids.
Going deeper: Internals *Primitive types, alignment and padding*.

## 3. dates-and-times — Dates, times and time zones
Facts
1. `timestamptz` stores an instant (UTC internally) and displays it in the session `TimeZone`; the original zone is not kept (datatype-datetime).
2. `timestamp` is wall-clock only; `TIMESTAMP '… +02'` silently drops the offset (datatype-datetime).
3. `timestamp AT TIME ZONE z` → timestamptz; `timestamptz AT TIME ZONE z` → timestamp (functions-datetime).
4. POSIX sign: `AT TIME ZONE '+05'` means UTC−5 (verified 12:00 UTC → 07:00) (datatype-datetime).
5. DST gap: `2026-03-08 02:30` in America/New_York reads as `03:30-04`; overlap `2026-11-01 01:30` reads as `-05` (verified).
6. `+ interval '1 day'` keeps local time; `+ '24 hours'` adds elapsed time: 12:00 vs 13:00 across the gap (functions-datetime).
7. Month arithmetic clamps: Jan 31 + 1 month → Feb 28 (2026), Feb 29 (2024) (functions-datetime).
8. `date - date` → integer days; `date + 30` → date; `date + interval` → timestamp (functions-datetime).
9. `now()` is fixed for the whole transaction; `clock_timestamp()` moves (functions-datetime).
10. `date_trunc('week', …)` → Monday; `date_trunc('day', tstz, 'Asia/Tokyo')` truncates in that zone (functions-datetime).
11. `extract` returns numeric; `dow` Sunday=0, `isodow` Monday=1; `week` pairs with `isoyear` (2027-01-01 is week 53 of 2026) (functions-datetime).
12. `date_bin('15 minutes', ts, origin)` buckets arbitrary strides (functions-datetime).
13. `age('2026-03-01','2026-01-31')` → `1 mon 1 day` (functions-datetime).
14. Use half-open ranges `ts >= start AND ts < end` for days and months (functions-datetime OVERLAPS, rangetypes).
Visualizer: Stepper "one instant, many clocks": lanes UTC / New York / London / Kolkata / Tokyo over a 48 h window; an animated instant marker; ghost markers for a timestamp without zone; AT TIME ZONE type flip badge; DST gap and overlap shading; 1 day vs 24 hours. Extra control: session TimeZone picker that changes the "psql shows" line.
Playground: `events(id, happened_at timestamptz, kind)` with generate_series data; presets: TimeZone display, timestamp vs timestamptz, AT TIME ZONE, DST arithmetic, truncation/extract/date_bin, half-open daily report, now vs clock_timestamp.
Production: daily revenue report off by a day for a non-UTC office → group by `date_trunc('day', ts, 'zone')` and half-open bounds.
Pitfalls: `timestamp` column for events; `BETWEEN '…' AND '…-31'` missing the last day; `'now'` frozen in DEFAULT; DST + '24 hours' in schedules.
Going deeper: Internals *Declarative partitioning and pruning* (half-open range bounds).

## 4. conditional-logic — Conditional logic
Facts
1. Searched CASE: first true WHEN wins; NULL is not true; no ELSE → NULL (functions-conditional).
2. Simple CASE uses `=`, so `CASE NULL WHEN NULL` does not match (verified `not matched`).
3. All THEN results must share a type: `CASE … THEN 1 ELSE 'a'` errors; `1` vs `2.5` → numeric (typeconv-union-case).
4. `COALESCE` returns the first non-NULL argument, stops evaluating there (functions-conditional).
5. `NULLIF(a,b)` → NULL when equal: `x / NULLIF(y,0)` avoids division by zero (functions-conditional).
6. `GREATEST/LEAST` ignore NULLs (differs from the standard) (functions-conditional).
7. `count(*) FILTER (WHERE …)` conditional aggregates (sql-expressions aggregate FILTER).
8. CASE skips unneeded arms at run time, but a constant `1/0` arm can fail at planning (verified on a table) (functions-conditional, sql-expressions).
9. Boolean expressions can be select-list columns; `(x > 2)::int` → 0/1 (datatype-boolean).
10. `sum` over zero rows → NULL; `coalesce(sum(x), 0)` (functions-aggregate).
11. `IS DISTINCT FROM` treats NULL as a value (functions-comparison).
Visualizer: row walker over 5 orders. Modes: tier CASE, COALESCE chain, safe division with NULLIF, FILTER aggregates. Each step evaluates one row: branches light up true / false / NULL in order, result cell fills in; FILTER mode animates accumulators. viz-next = "Next row".
Playground: `orders(id, customer, status, total, qty, coupon, promo)`; presets mirror the modes plus GREATEST/LEAST, boolean columns, CASE type error.
Production: KPI dashboard query with one pass of FILTER aggregates and NULLIF-protected ratios.
Pitfalls: WHEN order; `CASE x WHEN NULL`; division by zero in ratios; sum of nothing is NULL.
Going deeper: Internals *From SQL text to rows* (constant folding at plan time).

## 5. casting-and-types — Type conversion
Facts
1. `CAST(x AS t)`, `x::t`, and `t 'literal'` are the same conversion (sql-expressions, typeconv).
2. A quoted literal starts as type `unknown` and takes the type its context needs: `1 = '1'` works (typeconv-overview).
3. No implicit integer → text for functions: `length(12345)` and `substr(1234, 3)` error (typeconv-func).
4. text → integer accepts surrounding spaces, `_` separators and `0x` prefixes, but not `'42.5'` or `'1,234'` (verified).
5. numeric → integer rounds half away from zero (2.5 → 3); float8 → integer rounds half to even (2.5 → 2) (verified).
6. Out of range → error: `'99999'::smallint`, `40000::numeric(4,1)` (datatype-numeric).
7. `varchar(n)`/`char(n)` explicit casts truncate silently: `'abcdef'::varchar(3)` → `abc` (datatype-character).
8. `to_char(1234567.891, 'FM9,999,999.00')` → `1,234,567.89`; too few digits → `###` (functions-formatting).
9. `to_number('$1,234.56','L9,999.99')` → 1234.56; `to_date('14/11/2026','DD/MM/YYYY')`; invalid dates error (functions-formatting).
10. Ambiguous `03/04/2026` depends on `DateStyle` (MDY → March 4, DMY → April 3) (datatype-datetime).
11. `pg_input_is_valid(text, type)` and `pg_input_error_info` test input without raising (functions-info).
12. Text comparison is not numeric: `'10' < '9'` is true (verified).
13. boolean input accepts `yes/no/on/off/1/0/t/f` (datatype-boolean).
14. `->>` on jsonb returns text; cast it before arithmetic (functions-json).
Visualizer: cast matrix, captured with `pg_input_error_info`. Mode A: 12 text inputs × 6 target types (ok / changed / error). Mode B: numeric values from a `numeric` or `double precision` source to integer, smallint, numeric(4,1), real (rounding differences). Click a cell for SQL, result, error text and SQLSTATE. viz-next = "Next cell".
Playground: `staging_orders(raw_qty text, raw_price text, raw_date text, raw_paid text)` from a CSV-like import; presets: cast basics, unknown literals, what fails, validate before casting, to_char/to_number/to_date, DateStyle, JSON at a glance.
Production: importing a messy CSV into typed tables: validate rows with pg_input_is_valid, quarantine the rest.
Pitfalls: one bad row aborts the whole INSERT…SELECT; text sort of numbers; float→int rounding; DateStyle ambiguity.
Going deeper: Internals *JSON vs JSONB*.

## 6. working-with-json — Working with JSON
Scope split: storage, operators, jsonb_set NULL trap, lax/strict and JSON_TABLE live in Internals *JSON vs JSONB*; GIN internals in *GIN*. This lesson covers building, SQL/JSON functions, shredding, updating, validation and an index decision guide.
Facts (all verified on PG 18.6)
1. `to_jsonb(row)` keys by column name; `row_to_json` returns json and keeps column order (functions-json).
2. `jsonb_agg(x ORDER BY …)`; over zero rows an aggregate returns NULL; LEFT JOIN + jsonb_agg gives `[null]`; `jsonb_agg_strict` does not drop `{"id": null}` objects; `COALESCE(jsonb_agg(x) FILTER (WHERE … IS NOT NULL), '[]')` (functions-aggregate).
3. `jsonb_object_agg(k, v)`: NULL key is an error, NULL value kept; `_strict` drops it (functions-aggregate).
4. `JSON_OBJECT`/`JSON_ARRAY`/`JSON_ARRAYAGG` return json unless `RETURNING jsonb`; JSON_OBJECT NULL ON NULL default, JSON_ARRAY ABSENT ON NULL default (functions-json).
5. `JSON_VALUE` returns text (or RETURNING type), NULL ON ERROR and NULL ON EMPTY by default; non-scalar → NULL; string "3" RETURNING numeric → 3 (functions-json).
6. `JSON_QUERY` returns jsonb; several items need WITH [CONDITIONAL] WRAPPER, otherwise NULL; `EMPTY ARRAY ON EMPTY` (functions-json).
7. `JSON_EXISTS … PASSING v AS name`; lax `$.items.sku` unwraps arrays; strict missing key raises inside jsonb_path_query (functions-json).
8. `IS JSON [OBJECT|ARRAY|SCALAR] [WITH UNIQUE KEYS]` on text (functions-json).
9. `jsonb_to_recordset` casts `"3"` → int 3, missing → NULL; `jsonb_array_elements … WITH ORDINALITY` numbers from 1 (functions-json, queries-table-expressions).
10. `||` shallow, `-` key, `#-` path, `jsonb_insert` (insert_after, errors on existing key), `jsonb_set` no-op on missing parent (functions-json).
11. CHECK constraints with `jsonb_typeof`, `?&`, `NOT JSON_EXISTS(… ? (!exists(@.qty) || @.qty.type() != "number" || @.qty < 1))` (ddl-constraints).
12. Index guide, 20k products, 500 pages: `@>` 500 → 53 (GIN path_ops); `?` 500 → 83 (jsonb_ops only); `@@` equality 500 → 4; `->>` = 500 → 3 (B-tree expr); numeric range 500 → 104; jsonpath range: Seq Scan with every index; top-N 503 → 7 (gin-builtin-opclasses, indexes-expressional).
13. Stored generated column: estimate 50 (exact) vs 100 guess for `->>`, 2 for `@>`; VIRTUAL generated columns cannot be indexed (ddl-generated-columns).
Visualizer: three views. Rows → document (5 fold levels with layoutId animation, empty-group toggle plain / FILTER / FILTER+COALESCE); Path explorer (click nodes of inbox doc 1; 8 function results per path captured); Index guide (8 query shapes, plan + buffers before/after, captured).
Playground: customers/orders/order_items, inbox (2 JSON orders), products (20k jsonb). Presets: rows → JSON, empty groups, SQL/JSON functions, shred and load, update toolkit, validate (DO block with notices), index guide + promote.
Production: account-page API, 9 round trips → 1 statement, `[]` instead of fake order. Pitfalls: `[null]`, JSON_VALUE hides bad data, jsonb_set missing parent, one index for every query.

## 7. ranges-and-special-types — Ranges and other special types
Facts (verified)
1. Bounds `[ ] ( )`, default `[)`; discrete types canonicalize: `[1,10]` → `[1,11)`, `(1,10]` → `[2,11)`; lower > upper is an error (rangetypes).
2. Omitted bound = unbounded (`upper_inf` true, `upper` NULL); `infinity` is a value (`upper_inf` false); `empty` contains nothing, is contained by everything, sorts first (rangetypes, functions-range).
3. Operators `@> <@ && -|- << >> &< &>`, `+ * -`; union/difference that would leave a gap raise "would not be contiguous" (functions-range).
4. Multiranges: input normalizes `{[1,3),[2,6),[8,9)}` → `{[1,6),[8,9)}`; `range_agg`, `unnest`, `range_merge`, multirange `-` (rangetypes, functions-range).
5. `EXCLUDE USING gist (room_id WITH =, during WITH &&)` needs btree_gist for int; error 23P01 with DETAIL key text; PG18 `PRIMARY KEY (room_id, during WITHOUT OVERLAPS)` creates a GiST index and rejects empty ranges (ddl-constraints, sql-createtable, btree-gist).
6. inet keeps host bits, cidr rejects them; host/network/broadcast/netmask/masklen; `>>=` + `ORDER BY masklen DESC` = longest prefix; GiST `inet_ops` serves `<<` (datatype-net-types, functions-net).
7. Text IPs sort wrongly (`'10.1.2.30' < '10.1.2.4'`).
8. point/box/circle/polygon, `<->`, `@>`, `&&`, `~=` (no `=` for point); GiST on point gives KNN index scan (datatype-geometric, functions-geometry).
9. Composite: `(col).field` in SELECT, `col.field` in UPDATE SET; row `=` with NULL is NULL; row comparison left to right (rowtypes).
10. xml: well-formedness check on input, `xpath`, `XMLTABLE`, `xml_is_well_formed`, `xmlserialize … INDENT` all run (datatype-xml, functions-xml).
Visualizer: Two ranges (drag bounds, bracket toggles, int4range vs numrange, + * - and multirange ops; JS range model in `_range.ts` checked against PG on 22,500 random comparisons, 0 mismatches); Bookings (exclusion-constraint simulator with free time from multirange difference); IP networks (cidr containment tree, longest-prefix match; `_net.ts` checked against PG).
Playground: rooms/bookings (EXCLUDE), price_bands (int4range), subnets/access_log (cidr/inet, 20k rows), stores (5k points), plus composite and xml inline. Presets: basics, operators, multiranges/free time, no double bookings, network, geometry/KNN, composite + xml.
Production: race-free room booking with an exclusion constraint. Pitfalls: closed bounds collide, btree_gist missing, non-contiguous union, IPs as text.
