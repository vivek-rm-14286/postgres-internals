## 1. architectures — Architectures and classification

Key facts:
- DDB = logically interrelated databases over a network; the D-DBMS makes distribution **transparent** (Özsu ch.1).
- Not a DDBS: distributed files, a parallel multiprocessor, a single server reached over a network (client/server).
- Shared-memory (CPUs share memory and disks), shared-disk (own memory, shared disks), shared-nothing (own memory and
  disks; only messages).
- Classification axes: distribution, heterogeneity (data model, query language, transaction management), autonomy
  (design, communication, execution; tight / semiautonomous / isolated).
- Multidatabase = federated: autonomous, possibly heterogeneous DBMSs, each with an **export schema**, integrated
  bottom-up. postgres_fdw is a federated layer: wrapper → server → user mapping → foreign table; WHERE and joins on the
  same server are pushed; `fdw_tuple_cost` 0.2.
- Transparencies: data independence, network (location + naming), replication, fragmentation; plus concurrency and
  failure transparency (atomicity).
- NoSQL families: key-value (DynamoDB also document), document (MongoDB, BSON, 16 MiB doc limit), wide-column
  (Cassandra: partitioned wide-column, Dynamo + Bigtable), graph (Neo4j: nodes, typed directed relationships,
  properties). Distributed SQL keeps SQL + ACID on shared-nothing (CockroachDB, YugabyteDB, Citus).

Visualizer: tabs. (1) Architecture switcher: shared-memory / shared-disk / shared-nothing / federated; SVG of 3 nodes
with CPU, memory, disk boxes; shared resources highlighted; "add a node" shows what must be coordinated (memory bus,
cache fusion/lock manager, rebalancing, nothing). Stats per architecture. (2) Transparency ladder: same question, the
SQL the application must write at each transparency level (none → location → fragmentation → replication → full).
(3) Family explorer: one customer record in KV, document, wide-column, graph and relational form, with "what a lookup /
join / cross-key transaction costs".

Playground: two schemas as two sites, a global view, foreign-data-wrapper catalog objects, jsonb / wide-row / edge
table forms. Presets: federated catalog; location + fragmentation transparency via a view; replication transparency via
a setting-driven view; NoSQL shapes in PostgreSQL; graph traversal with a recursive CTE.

## 2. fragmentation-replication — Fragmentation, allocation and replication

Key facts: correctness rules (completeness, reconstruction, disjointness; vertical repeats key); PHF via minterms;
DHF Ri = R ⋉ Si with FK integrity; VF reconstruct by join; hybrid nesting; allocation partitioned / full / partial,
rule of thumb read/update ratio; sync vs async; active-passive vs active-active; snapshot replication (= matview
refresh); consistent hashing smoothness/monotonicity; vnodes fix non-uniform load and heterogeneity; Dynamo strategy 3
(Q equal partitions, Q/S tokens per node); Cassandra num_tokens 16.

Visualizer: (1) Fragmentation builder over 12 customer rows: pick a scheme (by region, missing region, overlapping,
vertical without key, vertical with key, hybrid), toggle fragments; live checks computed. (2) Hash ring: 10,000 keys
hashed with a bit-exact `hashint4` port; nodes 2–10, vnodes 1–64; add/remove node; % keys moved for ring vs modulo vs
fixed 64 ranges; max/mean load. (3) Replication modes stepper: sync/async/snapshot, crash primary → data lost.

Playground: LIST partitions (horizontal), completeness check + default partition, overlapping fragments disjointness
query, vertical tables + reconstructing view, derived fragmentation check via EXISTS, SQL hash ring with LATERAL and
moved-key count, matview snapshot replication + publication row filter.

## 3. commit-and-consensus — Distributed transactions and consensus

Key facts: 2PC blocks when coordinator fails after votes; 3PC adds committable "prepare to commit" buffer state, needs
site-failure-only model; no protocol resilient to partitions with lost messages (Skeen & Stonebraker Thm 4); Paxos
phases 1a/1b/2a/2b, value rule, duelling proposers, distinguished proposer; Raft leader + term + election restriction;
leases rely on bounded clock skew; fencing tokens; basic TO with max-r/max-w, restart with new timestamp; Thomas write
rule; certifiers (OCC); global wait-for graph, phantom deadlocks, Citus factor 2 × deadlock_timeout, youngest victim.

Visualizer tabs: commit protocol simulator (2PC/3PC × failure point incl. partition), Paxos simulator (5 acceptors,
2 proposers, acceptors up/down), TO scheduler (schedules, TWR toggle, OCC mode), global deadlock stepper, lease and
fencing stepper.

Playground (`max_prepared_transactions = 10`): in-doubt prepared xacts resolved; 3PC termination rule as a query; Paxos
acceptors as SQL functions; advisory lock + fencing-token trigger; TO scheduler function with TWR; global wait-for
graph cycle detection with a recursive CTE.

## 4. distributed-query-processing — Distributed query processing

Key facts: decomposition (normalize, analyse, eliminate redundancy, rewrite), localization (localization program =
union / join of fragments; reduction: contradicting predicates, join pairs, VF projection), cost = I/O + CPU +
communication; semijoin wins iff size(Π_A S) + size(R ⋉ S) < size(R); bit-array filter; ship-whole vs fetch-as-needed;
co-located / broadcast / repartition joins; partial aggregation pushdown; partition pruning, partitionwise join and
aggregate in PostgreSQL.

Visualizer tabs: localization stepper (operator tree from global query → localized → reduced → pushed down, with rows
moved), semijoin calculator (sliders; bytes for ship-whole, semijoin, bit-array), join strategy simulator over 4 nodes
(bytes moved computed), aggregate pushdown.

Playground: list-partitioned customers/orders (derived), presets for pruning, runtime pruning, partitionwise join,
partial aggregation, semijoin byte measurement, bit-array false positives, broadcast vs repartition byte totals.

## 5. operating-distributed — Operating distributed databases

Key facts: timeouts vs phi-accrual (φ = −log10(1 − F(Δt)), Φ=1 ≈ 10% mistakes, Cassandra phi_convict_threshold 8);
local view of failure (Dynamo); partitions and split brain; majority quorum; terms/epochs as fencing; catch-up by log
position; rebalancing (link E3); routing tables; TLS: ssl_min_protocol_version default TLSv1.2, hostssl, clientcert,
sslmode verify-full, Citus node_conninfo sslmode require, Cassandra internode_encryption; data residency: geo
partitioning (YugabyteDB tablespaces, CockroachDB REGIONAL BY ROW).

Visualizer tabs: phi-accrual detector over a seeded heartbeat stream (step 100 ms, jitter, hiccup, crash, Φ slider, vs
fixed timeout), partition and split-brain simulator (5 nodes, cut, quorum on/off, heal → catch-up counts), pg_hba
evaluator (first-match), geo-placement checker.

Playground: heartbeat table + φ computed with `erfc`; timeout vs φ false-suspicion counts; term-fenced writes; WAL LSN
diff for catch-up; routing table + rebalance key-move count; ssl settings and pg_hba_file_rules; geo LIST partitions +
residency check.
