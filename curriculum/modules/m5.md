# M5 — Concurrency, MVCC & Locking Internals (build plan)

PGlite facts captured for this module (PostgreSQL 18.6, one backend):
- A fresh read-only transaction has vxid `0/7` and `pg_current_xact_id_if_assigned()` = NULL; the first UPDATE assigns xid 755 and
  adds a `transactionid` ExclusiveLock (fastpath = false). Weak relation locks (AccessShare, RowShare, RowExclusive) show `fastpath = true`;
  `LOCK … IN SHARE MODE` and ACCESS EXCLUSIVE show `fastpath = false`.
- SAVEPOINT + write assigns subxid 756 (second `transactionid` lock); `ROLLBACK TO` drops that lock; bob's old version keeps `xmax = 756`
  (aborted, so ignored). The new version had `cmin = 1` (second command).
- Snapshot text in a quiet single session: `755:755:` (xmin = xmax, empty xip). `pg_visible_in_snapshot(own xid)` = false.
  `pg_visible_in_snapshot(755, '755:760:757')` = true, 757 → false (in xip), 760 → false (≥ xmax).
- SERIALIZABLE: `WHERE id = 1` takes SIReadLock on tuple (0,1) + btree page 1; a `sum()` seq scan promotes to a relation SIReadLock.
- `FOR UPDATE` writes the locker xid into `t_xmax` with `HEAP_XMAX_EXCL_LOCK | HEAP_XMAX_LOCK_ONLY`; pg_locks shows only RowShareLock on the
  table. FOR KEY SHARE then FOR SHARE in a savepoint → `xmax = 1` (MultiXact), `pg_get_multixact_members(1)` = (763 keysh), (764 sh).
- ALTER TABLE: ADD COLUMN, ADD CONSTRAINT … NOT VALID, SET NOT NULL → AccessExclusive; SET STATISTICS, SET (fillfactor), VALIDATE CONSTRAINT →
  ShareUpdateExclusive; CREATE INDEX → Share.
- Advisory: session lock taken twice needs two unlocks (third unlock returns false + WARNING); after ROLLBACK the xact lock is gone, the
  session lock (8) stays.
- HOT (items: id pk, sku indexed, qty): UPDATE qty → lp1 `HEAP_HOT_UPDATED`, ctid (0,4), new tuple `HEAP_ONLY_TUPLE`; no index entry.
  UPDATE sku → new tuple (0,6), **both** indexes get a new entry pointing at (0,6) (pkey has key 2 twice). VACUUM: lp1 → REDIRECT to 5,
  lp2 and lp4 → UNUSED, index entries for (0,2) removed. `n_tup_upd 3, n_tup_hot_upd 2`.
- Fillfactor experiment (10,000 rows, 2 indexes, update 20% of rows, 3 rounds): ff100: round 1 0% HOT, pkey 30 → 57 pages; ff90: 57% HOT
  round 1, 84% after 3; ff80 and below: 100% HOT, indexes unchanged. Rows/page: 88 (100), 79 (90), 70 (80), 62 (70), 53 (60), 44 (50).
  Whole-table UPDATE: only ff50 stays 100% HOT (ff70 → 42%, ff90 → 11%).
- Per-row EXCEPTION block for 500 updates consumed 502 xids (500 subxids); one set-based UPDATE consumed 1.
- `deadlock_timeout` 1s, `lock_timeout` 0, `max_prepared_transactions` 0 (PREPARE TRANSACTION unavailable), `log_lock_waits` off.
  `pg_wait_events`: 84 LWLock, 12 Lock, `SpinDelay` under Timeout.

Shared local components: `_timeline.tsx` (SessionTimeline: lanes A/B/C, ticks, statement cards, wait bars, snapshot/xid badges,
TupleVersions, Graph for waits-for / rw-conflicts), `_matrix.tsx` (clickable conflict matrix for table and row lock modes).

## 1. acid-transactions — ACID and transactions
Facts: every statement outside BEGIN is its own transaction (transaction-id.html); vxid = procNumber/localXID, always assigned
(transaction-id.html); a real xid is assigned only at first write (transaction-id.html, functions-info.html); xids are 32-bit and wrap,
xid8 carries the epoch (transaction-id.html); commit status lives in pg_xact (transaction-id.html); subtransactions via SAVEPOINT or
EXCEPTION blocks; parent xid < child subxid; pg_subtrans; 64 cached subxids per backend (subxacts.html); read-only xacts show only a
virtualxid in pg_locks (xact-locking.html); locks taken after a savepoint are released on rollback to it (explicit-locking.html); 2PC
PREPARE TRANSACTION / COMMIT PREPARED, GID ≤ 200 bytes, pg_prepared_xacts (two-phase.html, sql-prepare-transaction.html); sequences are
not rolled back (transaction-iso.html); cmin/cmax command ids (ddl-system-columns.html).
Visualizer: Stepper with captured numbers. Panels: transaction (vxid, xid, subxids, command id), heap versions, pg_xact cells, own pg_locks.
Ending toggle: COMMIT vs crash before COMMIT.
Playground: accounts; presets: virtual vs real xid, savepoint/rollback to, cmin/cmax, CLOG status via pg_xact_status, subxact cost.
Production: per-row EXCEPTION blocks burning subxids. Pitfalls: >64 subxids, idle in transaction, assuming sequences roll back, 2PC leftovers.

## 2. snapshots-visibility — Snapshots and tuple visibility
Facts: snapshot = xmin:xmax:xip (functions-info.html); RC takes a snapshot per statement, RR at first non-control statement
(transaction-iso.html); visibility rule (xmin committed & visible, xmax empty/aborted/not visible); hint bits; xid8, pg_snapshot_xip.
Visualizer: Stepper timeline (A reads twice, B commits between) with RC/RR toggle, plus a snapshot visibility calculator.
Playground: snapshot functions, saved snapshot "time travel" with heap_page_items + pg_visible_in_snapshot + pg_xact_status.
Production: long transaction holding back the xmin horizon. Pitfalls: idle-in-transaction, RR report surprise, xid vs xid8 casts.

## 3. hot-fillfactor — HOT updates and fillfactor
Facts: HOT conditions (storage-hot.html); summarizing (BRIN) indexes don't block HOT; redirects; pruning during normal reads;
fillfactor 10–100, default 100 for tables (sql-createtable.html); n_tup_hot_upd, n_tup_newpage_upd (monitoring-stats.html).
Visualizer: Stepper with mode HOT vs non-HOT, heap page + pkey + sku index, captured items; plus fillfactor explorer with measured numbers.
Playground: items table, HOT update, non-HOT update, pageinspect of both indexes, VACUUM redirect, fillfactor comparison.
Production: indexed updated_at killing HOT. Pitfalls: indexing a hot column, fillfactor change only affects new pages, long xacts block pruning.

## 4. isolation-levels — RC, RR, Serializable
Facts: anomalies table, RU = RC, RR no phantoms in PG, RC re-check (EvalPlanQual), RR 40001 "concurrent update", SSI 40001
"read/write dependencies", SIReadLock in pg_locks, seq scan → relation SIRead lock, READ ONLY DEFERRABLE, retry whole transaction.
Visualizer: SessionTimeline with three scripted scenarios (hits 9/10, RR 40001, SSI write skew with SIRead locks and rw edges).
Playground: isolation levels, snapshot stability under RR, SIRead locks of own xact, granularity promotion, retry function shape.

## 5. table-locks — heavyweight locks and the conflict matrix
Facts: 8 modes and Table 13.2, which commands take which, self never conflicts, held to xact end, lock queue FIFO, lock_timeout,
pg_blocking_pids, fast-path, ALTER TABLE levels, max_locks_per_transaction.
Visualizer: interactive conflict matrix + SessionTimeline "queue behind ACCESS EXCLUSIVE" with lock_timeout toggle.

## 6. row-locks-skip-locked — row locks, SKIP LOCKED, advisory locks
Facts: 4 row modes and Table 13.3, stored in t_xmax, not in pg_locks, MultiXacts, NOWAIT 55P03, SKIP LOCKED for queues, LIMIT + locking,
advisory session vs xact semantics.
Visualizer: SessionTimeline 3 workers with/without SKIP LOCKED + row-lock matrix.

## 7. lwlocks-deadlocks — LWLocks, spinlocks and deadlock detection
Facts: spinlock → LWLock → heavyweight; wait_event_type values; deadlock_timeout 1 s; waits-for graph; 40P01; lock ordering.
Visualizer: SessionTimeline deadlock with waits-for graph cycle; lock hierarchy explorer.
