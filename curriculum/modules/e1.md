# e1 — Vector Search with pgvector (build plan)

Source of truth: `research/V-pgvector.md` (pgvector README, CHANGELOG, source; 0.8.7 in PGlite). Blog errors from its
Contradictions section are avoided (`<=>` is a distance, not a similarity; index limits differ per type; Jaccard is for bit).

Shared dataset (`_kit.tsx` `ITEMS_SETUP`, ~0.3 s): `items` 10 000 × vector(32), 40 clustered topics (centre ± U(-0.5,0.5)),
`region = topic % 4`, `category` random 0–9; `queries` (20), `truth` (exact top-10, built before any index), view `recall`.
Single INSERT…SELECT…GROUP BY generator (no correlated subqueries). Clustered, because uniform data gives misleading recall.
Lesson 6 uses `docs` 2 000 × vector(256) (~1 s) so binary quantization is meaningful.
HNSW level assignment and IVFFlat k-means sampling are random, so measured recall varies in the 2nd–3rd decimal between builds; text says "about".

## 1. embeddings-and-vectors
Facts: extension name `vector`, 0.8.7; `vector(n)` float4, 4n+8 B, 16 000 dims stored / 2000 indexed; halfvec 2n+8, float16, max 65504,
indexed to 4000; sparsevec `{i:v}/n` 1-based, 8·nnz+16, HNSW only ≤1000 nnz; bit n/8+8, `binary_quantize` (>0 → 1), indexed to 64 000;
errors (dims mismatch, NaN, 16001 dims, 65520 halfvec); storage EXTERNAL (TOAST, uncompressed; 100 × 1536-d → heap 8 kB, toast 800 kB);
`l2_normalize`, `vector_norm`, `avg(vector)`. pgvector does not create embeddings.
Viz: 12 words with 8-d meaning-dimensions; real 2-D PCA map + nearest neighbours; bar view; exact byte layout per type
(varlena len/dim/unused; sparsevec len/dim/nnz/unused/idx/val; bit len/bitcount/bytes), float16 rounding; size bars at 384–3072 dims with index limits.
Presets: read, nearest, bytes per type (20/14/6152/3080/200/32), errors via try_sql, halfvec/sparse/bit casts, normalise+avg, TOAST.

## 2. distance-and-exact-search
Facts: six operators, values for [1,2,3] vs [3,1,2] (2.449, −11, 0.214, 4), bit Hamming 1 / Jaccard 0.333; `<#>` negative because index scans are ASC;
cosine 0..2, zero → NaN; unit vectors rank identically under L2/cos/IP; exact plan = Seq Scan + top-N heapsort 17 kB, 224 buffers, ~6 ms.
Viz: draggable query over 20 points, four operators, k-th-best boundary (circle, diamond, cone, half-plane), row-by-row exact scan with top-5 heap.
Presets: operators, edge cases, four rankings on `pts`, EXPLAIN exact, neighbours of a row, normalised same order.

## 3. hnsw
Facts: layers, promotion 1/m, entry point, greedy upper layers, ef_search beam on layer 0; m 16 (2–100), ef_construction 64 (≥2m), ef_search 40 (1–1000);
**ef_search caps rows** (LIMIT 100 → 40; SET LOCAL 100 → 100); recall 0.475/0.94/1.0 at ef 5/10/20; m=4,efc=8 → 2800 kB, recall 0.35/0.50/0.52;
index 4256 kB vs heap 1784 kB; index-use rules (ASC raw op + LIMIT + matching opclass; DESC, `1-op`, no LIMIT, wrong op, WHERE dist all seq scan);
zero vectors and NULLs not in a cosine index (2 of 4 rows).
Viz: in-browser HNSW (60 pts, m=3, efc=12, 3 layers) Stepper replaying descent + beam; ef_search/LIMIT sliders; recall tile; second tab: plan-shape rules + zero-vector panel.

## 4. ivfflat
Facts: k-means lists, rows/1000 (≤1M) or √rows, probes √lists, probes default 1; lists=100: recall 0.63–0.71 at 1 probe, ~0.97 at 3, 1.0 at 10;
15 vs 36 buffers (probes 1 vs 10); probes = lists → Seq Scan; built on 4/40 topics → ~0.7, REINDEX → 1.0; little-data NOTICE; no L1, relaxed-only iterative; 7 vs 14 opclasses.
Viz: exact Voronoi cells (half-plane clipping) of in-browser k-means; probes/lists sliders, probe-order labels, missed neighbours, recall/scan curve over 80 queries, list-size histogram, "built too early" mode.

## 5. filtering-and-hybrid
Facts: post-filtering; 10% filter: 3.7 rows/0.37 (ef 40), 8.7/0.87 (100), 10/1.0 (200), iterative strict/relaxed 10/1.0; anti-correlated region filter:
0 rows at any ef, strict ~0.8, relaxed ~0.9; EXPLAIN Rows Removed by Filter 39 vs 143; materialized CTE + `distance + 0`; 0.1% filter → Bitmap Index Scan + Sort;
partial HNSW index; partitioning for tenants; RRF k=60, FULL OUTER JOIN.
Viz: candidate-stream funnel (ef_search × iterative × filter) with measured tiles and guided tour; RRF merge with k slider (ranks from the playground query).

## 6. pgvector-production
Facts (2 000 × 256-d): bytes 1032/520/40; HNSW 2680 kB, halfvec 1640 kB, bit 664 kB; recall 1.0/1.0/0.44; bit re-rank 20/40/100/200 → 0.69/0.83/0.93/0.96;
expression must match; maintenance_work_mem 1MB NOTICE "after 660 tuples", ~3× slower; no parallel workers here; VACUUM keeps 2680 kB, REINDEX CONCURRENTLY → 1344 kB;
0.8.3/0.8.4 HNSW vacuum fixes; monitor recall with `enable_indexscan = off`.
Viz: strategy stepper (vector/halfvec/bit/bit+re-rank) with value strip, measured bars; sizing calculator (rows × dims).

## 7. pgvector-in-the-browser
Facts (measured, PGlite 0.5.16 / PG 18.6 / pgvector 0.8.7): pglite.wasm 8.7 MB raw, 3.24 MB gz; pglite.data 6.2 MB raw, 1.84 MB gz; JS ~0.14 MB gz;
vector.tar.gz 50 KB (vector.so 100 KB); fresh data dir ≈ 40 MB of files (4.5 MB as a gzipped dump); one `standalone backend`, no parallel workers;
`idb://` all browsers, `opfs-ahp://` Chrome/Firefox only, Worker-only (Safari: 252 sync handles); PGliteWorker leader election per `id`, followers proxy;
Transformers.js 4.3.2 (`@huggingface/transformers`), q8 default on WASM, all-MiniLM-L6-v2 q8 23 MB + tokenizer 0.7 MB + ORT WASM ~6.6 MB transfer, Cache API `transformers-cache`;
384-d vector = 1544 B; unit vectors: `<=>` = 1 + `<#>` → same ranking; 1000 rows: heap 1600 kB, HNSW (vector_ip_ops) 2008 kB, build ~0.4 s, exact scan ~2 ms.
Viz: Stepper timeline of the browser stack (network / UI / embedding worker / PGlite worker / storage) with first vs return visit bytes and ms; two-tab leader-election simulation;
live `idb://` persistence demo (write, close, reopen); opt-in live model (CDN Transformers.js in a Worker) + in-memory PGlite HNSW search.
Presets: what is running, 384-d unit vectors, `<#>` vs `<=>`, exact scan timing, HNSW + size, wrong operator, what gets persisted.
