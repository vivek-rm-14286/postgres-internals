## 1. spatial-basics — Geometry, geography and coordinate systems
Facts (using_postgis_dbmanagement, ST_Distance, ST_Transform, ST_MakePoint):
1. geometry = plane, Cartesian math, units of the SRID; geography = spheroid, metres, fewer functions.
2. geometry default SRID 0, geography default 4326; geography only accepts lon/lat SRSs.
3. Order is x = longitude, y = latitude.
4. ST_MakePoint has no SRID; ST_Point(x, y, srid) / ST_SetSRID add it; ST_SetSRID relabels, ST_Transform recomputes.
5. Typmod `geometry(Point,4326)` rejects wrong SRID and wrong type; registers in geometry_columns.
6. spatial_ref_sys: 8500 rows; srid, auth_name, auth_srid, srtext, proj4text.
7. London–Paris: 3.63 degrees (4326 geometry), 343.9 km geography, 537.3 km in 3857, 344.3 km in 3035.
8. 3857 inflates distances by about 1/cos(lat); 1°×1° cells shrink from 12 309 km² (equator) to 6 123 km² (60°).
9. Antimeridian: 359 degrees vs 111 km.
10. Formats: WKT, EWKT, HEXEWKB canonical output, GeoJSON (RFC 7946 = 4326).
Viz: graticule plane morphing between lon/lat and Web Mercator (motion path morph); four city pairs; distance read-outs per method;
"swap lat/lon" toggle shows the misplaced points and the wrong distance; latitude slider for the 1°×1° cell area.
Playground: `cities` (7 city coordinates typed in as points, not a map dataset) + a 1° grid, presets: SRIDs, three distances, area by latitude, typmod errors, formats, antimeridian.
Production: delivery app storing lat/lon in two float columns and measuring with 3857 → fix with geography column.
Pitfalls: swapped coordinates, degrees as metres, ST_SetSRID vs ST_Transform, 3857 for measurement.

## 2. spatial-indexes — Spatial indexes
Facts (dbmanagement index section, using_postgis_query, ST_DWithin, geometry_overlaps):
GiST over bboxes; `&&`/`~`/`@`; index-aware list; ST_Distance not indexed; ST_DWithin = `&& st_expand` + exact; cast to geography → Seq Scan;
functional geography index; SP-GiST; BRIN only for spatially sorted data (171 vs 16 lossy blocks); sizes 864 kB / 968 kB / 24 kB.
Viz: 60 points, STR R-tree drawn as nested boxes; drag the query point, set radius; three modes (index DWithin, `&&` only, geography cast);
step phases: expand → inner boxes → leaf boxes → candidates → recheck. Tiles + an EXPLAIN-shaped plan with the simulated counts.
Playground: `places` 20 000 points 4326 + GiST. Presets: && box, DWithin degrees, the cast trap, functional index fix, ST_Distance trap, SP-GiST/BRIN sizes, BRIN sorted vs unsorted.

## 3. nearest-neighbour — Nearest-neighbour search
Facts (geometry_distance_knn, geometry_distance_box): `<->` index only in ORDER BY with one constant side; LATERAL works per row;
geography `<->` on a sphere; `<#>` box distance; degrees mis-rank (9976 vs 11179); ST_DWithin + ORDER BY combination; KNN + filter (Rows Removed by Filter).
Viz: best-first search over the same R-tree with a priority queue; step pop/expand; results emitted in order; compare work vs Seq Scan + top-N.
Playground: `places` + `riders` (50). Presets: KNN plan, distances in degrees vs metres, geography KNN, filter, LATERAL nearest per rider, joined column trap.

## 4. spatial-queries — Everyday spatial queries
Facts: ST_Contains vs ST_Covers boundary, point-in-polygon join, ST_HexagonGrid, ST_Union/ST_Collect, ST_Buffer, ST_Area/ST_Length in metres,
ST_ClusterDBSCAN core/border/noise NULL, ST_ClusterKMeans, ST_Simplify validity, ST_AsGeoJSON + 4326, ST_IsValid/ST_MakeValid (bow-tie area 0).
Viz: (a) point-in-polygon join stepper over 7 hex zones: bbox candidates then exact test, counts per zone; (b) DBSCAN stepper with eps/minpoints.
Playground: SRID 27700 hex `zones` (33), `hubs`, `orders` (5000), `route` line. Presets: PIP join, buffers/area, union/collect, DBSCAN, k-means, GeoJSON, validity.
