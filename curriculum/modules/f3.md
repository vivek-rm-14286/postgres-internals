# F3 — Designing a Database (plan)

Audience: new to SQL. Define every term once, show results, end each lesson with one "going deeper" pointer.
All numbers below were checked against PostgreSQL 18 (PGlite) with scratch scripts before writing.

## 1. keys-and-relationships — Keys and relationships
Facts
1. A primary key = UNIQUE + NOT NULL; one per table; creates a unique B-tree index named `<table>_pkey` (ddl-constraints).
2. Natural key = a real-world value (ISO code, email); surrogate key = a generated value with no meaning (ddl-constraints, ddl-identity-columns).
3. `GENERATED ALWAYS AS IDENTITY` uses an implicit sequence; identity is NOT NULL but not unique on its own (ddl-identity-columns).
4. `uuidv7()` (time ordered) and `gen_random_uuid()` (v4) are built in (functions-uuid).
5. `REFERENCES t` defaults to t's primary key; default FK name `<table>_<col>_fkey` (ddl-constraints, tutorial-fk).
6. Referenced columns must be PK/UNIQUE; referencing columns are NOT indexed automatically (ddl-constraints).
7. FK check is skipped when any referencing column is NULL (MATCH SIMPLE) (ddl-constraints).
8. ON DELETE: NO ACTION (default, 23503, deferrable), RESTRICT (23001, not deferrable), CASCADE, SET NULL, SET DEFAULT (ddl-constraints).
9. Many-to-many = junction table with two FKs and composite PK (ddl-constraints).
10. One-to-one = FK column that is also UNIQUE (or is the PK) (ddl-constraints).
11. Self-reference: `manager_id REFERENCES employees` (ddl-constraints).
Visualizer: mode toggle 1:N / M:N / 1:1 / self; crow's-foot ER SVG + live row cards; click a row to light up linked rows;
ON DELETE lab (pick action, delete author) shows real error text + SQLSTATE or cascading rows.
Playground: authors / books / tags / book_tags / employees. Presets: join 1:N, junction join, ON DELETE RESTRICT via try(),
CASCADE on junction, self-join manager, catalog of FKs.
Production: missing index on FK → slow parent delete. Pitfalls: unindexed FK, CASCADE surprises, nullable FK, natural key that changes.
Deeper: I1 normalization-constraints.

## 2. constraints-defaults — Constraints and defaults
Facts
1. NOT NULL → 23502; CHECK → 23514; UNIQUE → 23505; FK → 23503; EXCLUDE → 23P01 (errcodes-appendix).
2. Defaults fill missing columns first; the identity value is drawn even if the row is rejected (ddl-default, observed).
3. CHECK passes when the expression is NULL (ddl-constraints).
4. UNIQUE allows many NULLs; `NULLS NOT DISTINCT` forbids a second NULL (ddl-constraints).
5. UNIQUE / PK create a unique B-tree index (ddl-constraints).
6. PG18 stores NOT NULL in pg_constraint (contype 'n') with names like `accounts_email_not_null` (catalog-pg-constraint).
7. Name constraints with `CONSTRAINT name` so errors are readable (ddl-constraints).
8. Enum invalid input → 22P02; enum values are added with ALTER TYPE ADD VALUE (datatype-enum).
9. Domain = type + constraints, `VALUE` keyword, error 23514 (sql-createdomain).
10. EXCLUDE USING gist (during WITH &&) forbids overlaps (ddl-constraints).
11. Default is evaluated at insert time; `DEFAULT now()` (ddl-default).
Visualizer: gatekeeper. Pick or build a row; it passes defaults → NOT NULL → CHECK → UNIQUE → FK; rejected at the first failing gate
with real message + SQLSTATE; identity counter burns a value each attempt.
Playground: plans + accounts + bookings; presets via try().

## 3. indexes-101 — Indexes for beginners
Facts (100k customers, 935 heap pages, captured)
- Seq Scan email: cost 0..2185, 935 buffers, Rows Removed 99999.
- Index on email: 3 levels (bt level 2), Index Scan cost 0.42..8.44, 4 buffers.
- signup_date ranges: 1 day 55 rows Bitmap (cost 182.75, 56 heap blocks); 1 year Bitmap 1519; all 5 years → Seq Scan 2435.
- lower(email) cannot use email index → Seq Scan.
- Composite (country, city) serves country+city; leading column matters.
- Index sizes: pk 2.2 MB, email 4.0 MB, table 7.5 MB; inserts slower with each index.
- CREATE INDEX blocks writes, not reads (sql-createindex).
Visualizer: Stepper story over a 935-cell page grid + mini B-tree; stats tiles.

## 4. views-and-sequences — Views, sequences and identity
Facts: view = stored query, runs each time (sql-createview); auto-updatable rules; CHECK OPTION → 44000; aggregate view
update → 55000; materialized view stores result, REFRESH; sequences never roll back (sql-createsequence); serial =
int + sequence + DEFAULT nextval; identity ALWAYS rejects manual ids (428C9), OVERRIDING SYSTEM VALUE; serial manual id →
later 23505; RETURNING id; currval session-local; RESTART WITH.

## 5. schema-changes — Changing a schema safely
Facts (100k-row orders, captured with pg_locks + relfilenode)
| op | lock | rewrite |
| ADD COLUMN / const default / NOT NULL DEFAULT 0 | AccessExclusive | no |
| ADD COLUMN volatile default / identity / stored generated | AccessExclusive | yes |
| ALTER TYPE int→bigint | AccessExclusive | yes; varchar(50)→(100), varchar→text: no |
| SET NOT NULL / ADD CHECK | AccessExclusive + full scan |
| ADD CHECK NOT VALID / NOT NULL NOT VALID (PG18) | AccessExclusive, instant |
| VALIDATE CONSTRAINT | ShareUpdateExclusive |
| ADD FK | ShareRowExclusive on both tables; NOT VALID skips scan |
| CREATE INDEX | Share (blocks writes); CONCURRENTLY: ShareUpdateExclusive, not in txn (25001) |
Lock queue: waiting AccessExclusive blocks every later query; `lock_timeout` caps the wait (runtime-config-client).
Visualizer: tab 1 planner (pick op → lock, blocks reads/writes, rewrite, scan, safe recipe); tab 2 lock-queue timeline Stepper.
